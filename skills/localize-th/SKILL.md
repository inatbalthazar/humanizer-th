# localize-th

แปลภาษาอังกฤษเป็นภาษาไทยสำหรับซับไตเติล หน้าจอแอปและเว็บไซต์ และเกม ให้คนไทยอ่านแล้วไม่รู้สึกว่าเป็นงานแปล ความหมายต้องครบ และไฟล์ต้องเอากลับไปใช้ได้ทันทีโดยไม่พัง

งานนี้มีเป้าหมาย 2 อย่างที่ต้องได้พร้อมกัน

1. **ภาษา:** อ่านเหมือนคนไทยเขียน ไม่ใช่แปลทีละคำ ตัวละครพูดเหมือนคน ปุ่มสั้นและชัด
2. **ไฟล์:** เวลาในซับ key ในไฟล์ UI ตัวแปรอย่าง `{name}` หรือ `%s` และแท็กต่างๆ ต้องอยู่ครบเหมือนต้นฉบับทุกตัว คำแปลที่สวยแต่ทำแอปพังถือว่าใช้ไม่ได้

## ใช้เมื่อไหร่

- ผู้ใช้ส่งซับไตเติล ไฟล์ข้อความ UI บทเกม หรือข้อความภาษาอังกฤษ แล้วขอให้แปลเป็นไทย
- ผู้ใช้ส่งคำแปลไทยที่มีอยู่แล้ว (พร้อมต้นฉบับหรือไม่ก็ได้) แล้วขอให้ตรวจหรือแก้

**ไม่ใช้เมื่อ**

- ต้นฉบับเป็นภาษาอื่นที่ไม่ใช่อังกฤษ ให้บอกผู้ใช้ว่า skill นี้เขียนกฎไว้สำหรับต้นฉบับภาษาอังกฤษ ถ้าผู้ใช้ยังอยากให้แปล ทำได้แต่ต้องบอกว่าไม่ได้ผ่านกฎชุดนี้ครบ
- แปลไทยเป็นอังกฤษ
- ข้อความไทยที่เขียนเป็นไทยตั้งแต่แรก แล้วอยากให้เป็นธรรมชาติขึ้น ใช้ skill `humanizer-th`

## เลือกโหมด

| โหมด | เมื่อผู้ใช้พูดว่า | ทำอะไร |
|---|---|---|
| `แปล` (translate, ค่าเริ่มต้น) | "แปลซับนี้" "แปลไฟล์นี้เป็นไทย" หรือส่งข้อความอังกฤษมาโดยไม่บอกโหมด | คำแปลในรูปแบบเดียวกับต้นฉบับ + บันทึกการแปลสั้นๆ |
| `ตรวจคำแปล` (review) | "ตรวจคำแปลให้หน่อย" "แปลแบบนี้โอเคไหม" | รายการจุดที่มีปัญหา พร้อมรหัสและคำแปลที่เสนอ **ไม่แก้ไฟล์** |
| `แก้คำแปล` (fix) | "แก้คำแปลนี้ให้" "ปรับซับให้ลื่นขึ้น" | ไฟล์คำแปลที่แก้แล้ว + รายการจุดที่แก้ |

## ขั้นตอน

ทำ 5 ขั้นตามลำดับ

### ขั้นที่ 1: ดูว่าเป็นงานอะไร

ระบุ 3 อย่างนี้ก่อนแปล

1. **ประเภทงาน:** ซับไตเติล / บทพากย์ / UI แอปหรือเว็บ / เกม / ข้อความทั่วไป (เกมมักมีทั้งบทพูดและ UI ในงานเดียว ให้ใช้กฎของทั้งสองส่วน)
2. **รูปแบบไฟล์:** SRT, VTT, ASS, JSON, PO, XLIFF, .strings, Android XML, ARB, CSV หรือข้อความเปล่า ดูกฎของแต่ละแบบใน `formats.md`
3. **บริบท:** แนวเรื่อง (ดราม่า ตลก แฟนตาซี) กลุ่มผู้ชม (เด็ก วัยรุ่น ผู้ใหญ่) ตัวละครและความสัมพันธ์ ชื่อแอปหรือแบรนด์ และอภิธานศัพท์ (glossary) ถ้าผู้ใช้มี

ถ้าบริบทขาดจนแปลผิดได้จริง เช่น ไม่รู้ว่าตัวละครสองตัวเป็นพี่น้องหรือคู่รัก ให้ถาม**คำถามเดียว**ที่สำคัญที่สุด ถ้าเดาได้พอสมควร ให้แปลไปก่อน แล้วบอกสิ่งที่เดาไว้ในบันทึกการแปล

### ขั้นที่ 2: เตรียมคำศัพท์และตัวละคร

- **อภิธานศัพท์:** ถ้าผู้ใช้ให้มา ใช้ตามนั้นทุกจุด แม้จะไม่ตรงกับ `glossary.md` ถ้าไม่มี ให้ใช้ `glossary.md` แล้วจดคำที่เลือกไว้ใช้ให้ตรงกันทั้งไฟล์
- **ชื่อเฉพาะ:** ตัดสินครั้งเดียวว่าชื่อไหนทับศัพท์ ชื่อไหนแปลความหมาย ชื่อไหนคงเป็นอังกฤษ แล้วใช้แบบเดียวกันทั้งงาน (ดู `games.md` หัวข้อชื่อเฉพาะ)
- **ตัวละคร (ซับและเกม):** ทำตารางตัวละครตาม `characters.md` ว่าใครเรียกตัวเองว่าอะไร เรียกอีกฝ่ายว่าอะไร ใช้คำลงท้ายแบบไหน ห้ามเดาเพศจากชื่ออย่างเดียว ให้ดูจากบริบท เช่น he/she หรือฉากที่เห็น

### ขั้นที่ 3: แปล

- แปลความหมายและเจตนา ไม่ใช่แปลทีละคำ อ่านทั้งฉากหรือทั้งหน้าจอก่อนแปลบรรทัดแรก
- เขียนแบบที่คนไทยพูดหรือเขียนจริงในสถานการณ์นั้น ไล่หารูปแบบภาษาแปลตาม `translation.md` (LT01–LT12) และรูปแบบ AI ตาม `patterns.md`
- ใช้กฎเฉพาะของงาน
  - ซับ: ความยาวบรรทัด การตัดบรรทัด ความเร็วการอ่าน ตาม `subtitles.md` ย่อได้แต่ใจความต้องครบ
  - บทพากย์: ความยาวที่พูดใกล้ต้นฉบับ เขียนให้อ่านออกเสียงได้ทันที ตาม `subtitles.md` หัวข้อบทพากย์
  - UI: สั้น ชัด ทำตามได้ทันที ตาม `ui.md`
  - เกม: น้ำเสียงตัวละคร ชื่อไอเทมและสกิล ตาม `games.md`
- ไฟล์ยาว: แปลทีละช่วง (เช่น ทีละ 100–200 บล็อกของซับ หรือทีละหน้าจอของ UI) แต่ใช้ตารางคำศัพท์และตัวละครชุดเดียวกันตลอด

### ขั้นที่ 4: ตรวจไฟล์

เทียบไฟล์ที่แปลกับต้นฉบับ

- [ ] จำนวนบล็อกซับ เลขลำดับ และเวลาเหมือนเดิมทุกบล็อก
- [ ] key ทุกตัวอยู่ครบ ไม่มี key ใหม่ ไม่มี key หาย ลำดับเดิม
- [ ] ตัวแปรและ placeholder (`{name}` `{{count}}` `%s` `%1$d` `[PlayerName]`) ครบทุกตัว สะกดเหมือนเดิมทุกตัวอักษร
- [ ] แท็ก (`<b>` `<i>` `{\i1}` `\N` `<color=#f00>`) ครบ เปิดและปิดคู่กัน
- [ ] โครงสร้างพหูพจน์แบบ ICU (`{count, plural, ...}`) ยังอยู่ แปลเฉพาะข้อความข้างใน
- [ ] ไฟล์ยังเป็น JSON, XML หรือ CSV ที่ถูกต้อง เครื่องหมายคำพูดภายในข้อความถูก escape

ถ้าเครื่องมือที่ใช้อยู่รันคำสั่งได้ ให้รันสคริปต์ที่มากับ skill นี้ เทียบต้นฉบับกับคำแปล แล้วแก้ทุกจุดที่ขึ้น `ERROR` ส่วน `WARN` ให้แก้ถ้าแก้ได้โดยไม่เสียใจความ

```
python3 scripts/check_translation.py ต้นฉบับ.srt คำแปล.srt
python3 scripts/check_translation.py ไฟล์.po
```

(path `scripts/` นับจากโฟลเดอร์ของ skill นี้) สคริปต์รองรับ SRT, VTT, ASS, JSON, ARB, PO, XLIFF, .strings, Android XML และ CSV ถ้ารันไม่ได้ ให้ไล่เช็กตามรายการข้างบนเอง

### ขั้นที่ 5: อ่านทวนเป็นภาษาไทย

อ่านคำแปลโดยไม่ดูต้นฉบับ เหมือนเป็นคนดูหรือผู้ใช้ชาวไทย

- [ ] อ่านแล้วไม่สะดุด ไม่มีประโยคที่ฟังเหมือนแปลมา
- [ ] ตัวละครแต่ละตัวพูดเหมือนเดิมตลอดเรื่อง สรรพนามไม่สลับไปมา
- [ ] คำศัพท์เดียวกันแปลเหมือนกันทุกจุด
- [ ] ไม่มีอีโมจิหรือ "!" ที่ต้นฉบับไม่ได้ต้องการ (ดู TH29 และ `subtitles.md`)
- [ ] ความหมาย ตัวเลข ชื่อ และข้อมูลครบตามต้นฉบับ

## ข้อห้าม

1. ห้ามเปลี่ยนเวลาในซับ key ตัวแปร แท็ก และโครงสร้างไฟล์
2. ห้ามตัดใจความหรือเพิ่มข้อมูลที่ต้นฉบับไม่มี ซับย่อคำได้ แต่เรื่องต้องไม่เปลี่ยน
3. ห้ามลดหรือเพิ่มความแรงของคำหยาบ ความรุนแรง หรือเรื่องทางเพศจากต้นฉบับ เว้นแต่ผู้ใช้กำหนดเรตไว้
4. ห้ามแปลชื่อแบรนด์ ชื่อแอป ชื่อเฉพาะที่ผู้ใช้หรืออภิธานศัพท์กำหนดให้คงไว้
5. ห้ามจงใจใส่คำผิด และห้ามเดาเพศตัวละครจากชื่ออย่างเดียว
6. ถ้ากฎสองข้อชนกัน เช่น ซับยาวเกินแต่ตัดคำไม่ได้โดยไม่เสียใจความ ให้รักษาใจความไว้ก่อน แล้วบอกในบันทึกการแปลว่าบล็อกไหนยาวเกิน

## รูปแบบคำตอบ

### `แปล`

```
[ไฟล์หรือข้อความที่แปลแล้ว ในรูปแบบเดียวกับต้นฉบับ]

---
บันทึกการแปล:
- ประเภทงาน: ซับไตเติล SRT 48 บล็อก
- ตัวละคร: มายา (ผู้หญิง) เรียกตัวเองว่า "ฉัน" เรียกเจคว่า "นาย" / เจค (ผู้ชาย) ใช้ "ผม" กับ "คุณ" ช่วงต้นเรื่อง
- คำศัพท์ที่เลือก: "Resistance" แปลว่า "กลุ่มต่อต้าน"
- สิ่งที่เดาไว้: ...
- บล็อกที่ยาวเกินกำหนด: ...
```

- ถ้าได้เป็นไฟล์ ให้ส่งไฟล์เต็มที่เอาไปใช้ได้ทันที ไม่ตัดบางส่วนแล้วเขียนว่า "...ที่เหลือเหมือนเดิม"
- ถ้าไฟล์ยาวเกินจะส่งในคำตอบเดียว ให้ส่งเป็นช่วงๆ บอกว่าช่วงนี้คือบล็อกไหนถึงบล็อกไหน และยังเหลืออีกเท่าไหร่
- บันทึกการแปลใส่เฉพาะสิ่งที่ผู้ใช้ต้องรู้ ไม่ต้องอธิบายทุกบรรทัด
- ข้อความสั้น (ไม่กี่บรรทัด) ไม่ต้องมีบันทึก ถ้าไม่มีอะไรต้องแจ้ง

### `ตรวจคำแปล`

```
พบ 5 จุด:

1. บล็อก 12 "มันเป็นไปไม่ได้" (LT03) "มัน" แปลจาก it → เสนอ "เป็นไปไม่ได้หรอก"
2. key `checkout.button` "ดำเนินการชำระเงิน" (UI) ยาวเกินปุ่ม → เสนอ "ชำระเงิน"
3. บล็อก 30 ตัวแปร `{count}` หายไป (ไฟล์)
...

ภาพรวม: [1–2 ประโยค]
```

- เรียงตามลำดับในไฟล์ ปัญหาที่ทำไฟล์พังให้ติดป้าย `(ไฟล์)` และขึ้นก่อนในภาพรวม
- ถ้าไม่พบปัญหา ให้เขียนว่า `ไม่พบจุดที่ต้องแก้`

### `แก้คำแปล`

ส่งไฟล์ที่แก้แล้วทั้งไฟล์ ตามด้วยรายการ `จุดที่แก้:` แบบเดียวกับ `ตรวจคำแปล`

## กรณีพิเศษ

- **เพลงในหนังหรือเกม:** แปลเมื่อเนื้อเพลงเกี่ยวกับเรื่อง หรือผู้ใช้ขอ ถ้าไม่เกี่ยว ให้คงไว้หรือเว้นตามที่ผู้ใช้กำหนด ไม่ต้องแปลให้สัมผัส เว้นแต่ผู้ใช้ขอ
- **มุกและการเล่นคำ:** หามุกไทยที่ให้ผลใกล้เคียงกัน ถ้าหาไม่ได้ ให้แปลความหมายให้เข้าใจ แล้วบอกในบันทึกการแปล
- **ป้ายและตัวหนังสือบนจอ:** แปลเมื่อเกี่ยวกับเรื่อง ใส่วงเล็บหรือตำแหน่งตามที่ผู้ใช้กำหนด
- **ต้นฉบับผิดหรือกำกวม:** แปลตามเจตนาที่น่าจะเป็น แล้วบอกในบันทึก
- **ผู้ใช้ให้คำแปลเก่ามาด้วย:** ใช้คำศัพท์และสรรพนามให้ต่อเนื่องกับของเดิม
- **เนื้อหาเฉพาะทาง** (กฎหมาย การแพทย์ การเงิน): แปลให้ตรงความหมาย แจ้งในบันทึกว่าควรให้ผู้เชี่ยวชาญตรวจอีกรอบ

## ตัวอย่างสั้น

**ผู้ใช้:** แปลซับนี้หน่อย ฉากพี่สาวโทรหาน้องชายที่หายไปหลายวัน

```
14
00:02:10,500 --> 00:02:13,200
Where have you been? I've been calling you all week!

15
00:02:13,400 --> 00:02:15,000
- It's complicated.
- Then uncomplicate it.
```

**ผลลัพธ์:**

```
14
00:02:10,500 --> 00:02:13,200
แกหายไปไหนมา
พี่โทรหาทั้งอาทิตย์แล้วนะ

15
00:02:13,400 --> 00:02:15,000
- มันซับซ้อนน่ะ
- งั้นก็เล่ามาให้เข้าใจ

---
บันทึกการแปล:
- พี่สาวเรียกน้องว่า "แก" แทนตัวเองว่า "พี่" ตามที่พี่น้องไทยพูดกัน
- ตัด "!" ออก ใช้ "นะ" แสดงอารมณ์แทน
- "uncomplicate it" เป็นการเล่นคำ แปลตามความหมายแทน
```
