# ข้อความในแอปและเว็บไซต์

ข้อความ UI ถูกอ่านแบบกวาดตา ผู้ใช้ไม่ได้อ่านทีละคำ ข้อความที่ดีจึงสั้น บอกชัดว่ากดแล้วเกิดอะไร และเป็นคำที่คนไทยเห็นในแอปอื่นจนคุ้นแล้ว

## 1. หลักการ

1. **สั้นและตรง** ปุ่มใช้คำกริยา 1–3 คำ หัวข้อใช้คำนาม ข้อความอธิบายไม่เกิน 1–2 ประโยค
2. **ไม่ใส่ครับ ค่ะ** ข้อความ UI เป็นเสียงของระบบ ไม่มีเพศ เว้นแต่แบรนด์ตั้งบุคลิกไว้ เช่น แอปที่มีตัวการ์ตูนพูดกับผู้ใช้
3. **ไม่ใช้ "คุณ" ทุกข้อความ** ภาษาอังกฤษใส่ you และ your เกือบทุกประโยค ภาษาไทยละได้ (TH14) เช่น "Your password" เป็น "รหัสผ่าน"
4. **ไม่ใช้ "!" และอีโมจิ** เว้นแต่ต้นฉบับใช้และแบรนด์ต้องการจริงๆ (TH29)
5. **คำเดียวกันแปลเหมือนกันทั้งแอป** ถ้า "Delete" เป็น "ลบ" ที่หน้าหนึ่ง ต้องเป็น "ลบ" ทุกหน้า
6. **ระดับภาษา** แอปทั่วไปใช้ `ไม่เป็นทางการ` ถึง `กึ่งทางการ` แอปธนาคาร ประกัน หน่วยงานรัฐ ใช้ `กึ่งทางการ` เกมใช้ `ไม่เป็นทางการ`

## 2. ปุ่ม

- บอกสิ่งที่จะเกิด ไม่ใช่แค่ "ตกลง" เช่น ในหน้าต่างยืนยันการลบ ให้ใช้ "ลบ" ดีกว่า "ตกลง"
- ใช้คำกริยาที่คนไทยคุ้น ดูตารางใน `glossary.md`
- ถ้ามีข้อจำกัดความยาว (จากคอมเมนต์ในไฟล์ หรือผู้ใช้บอก) ต้องไม่เกิน ถ้าเกินไม่ได้จริงๆ ให้เสนอคำสั้นกว่า 2 ตัวเลือกในบันทึก

| ต้นฉบับ | แปลแข็ง | ควรใช้ |
|---|---|---|
| Proceed to checkout | ดำเนินการต่อไปยังการชำระเงิน | ชำระเงิน |
| Click here to learn more | คลิกที่นี่เพื่อเรียนรู้เพิ่มเติม | ดูเพิ่มเติม |
| Get started | เริ่มต้นใช้งาน | เริ่มใช้งาน / เริ่มเลย |
| Submit | ส่งข้อมูล | ส่ง |

## 3. ข้อความแจ้งข้อผิดพลาด

บอกว่าเกิดอะไรขึ้น แล้วบอกว่าผู้ใช้ทำอะไรต่อได้ ไม่โทษผู้ใช้ และไม่ใช้ภาษาเทคนิคเกินจำเป็น

| ต้นฉบับ | แปลแข็ง | ควรใช้ |
|---|---|---|
| Failed to load data. Please try again. | การโหลดข้อมูลล้มเหลว กรุณาลองใหม่อีกครั้ง | โหลดข้อมูลไม่ได้ ลองอีกครั้ง |
| Unable to connect to the server. | ไม่สามารถเชื่อมต่อกับเซิร์ฟเวอร์ได้ | เชื่อมต่อไม่ได้ ตรวจอินเทอร์เน็ตแล้วลองอีกครั้ง |
| Invalid email address. | ที่อยู่อีเมลไม่ถูกต้อง | อีเมลไม่ถูกต้อง |
| Something went wrong. | มีบางอย่างผิดพลาด | เกิดข้อผิดพลาด ลองอีกครั้ง |
| This field is required. | ช่องนี้เป็นสิ่งจำเป็น | กรอกช่องนี้ด้วย / จำเป็นต้องกรอก |

คำที่ควรเลี่ยง: "ล้มเหลว" "ไม่สามารถ...ได้" (TH21) "การ...ล้มเหลว" (TH02) ใช้ "...ไม่ได้" "...ไม่สำเร็จ" แทน

| ต้นฉบับ | แปลแข็ง | ควรใช้ |
|---|---|---|
| Saved successfully! | บันทึกสำเร็จแล้ว! | บันทึกแล้ว |
| Your changes have been saved. | การเปลี่ยนแปลงของคุณได้รับการบันทึกแล้ว | บันทึกการเปลี่ยนแปลงแล้ว |
| Are you sure you want to delete this? | คุณแน่ใจหรือไม่ว่าคุณต้องการลบสิ่งนี้? | ลบรายการนี้ไหม |
| This action cannot be undone. | การกระทำนี้ไม่สามารถยกเลิกได้ | ลบแล้วกู้คืนไม่ได้ |

## 5. ตัวแปรและ placeholder

ตัวแปรคือส่วนที่โปรแกรมจะใส่ค่าจริงทีหลัง ต้องอยู่ครบและสะกดเหมือนเดิมทุกตัวอักษร

| แบบ | ตัวอย่าง | พบใน |
|---|---|---|
| วงเล็บปีกกา | `{name}` `{0}` `{{count}}` | JavaScript, i18next, .NET, Vue |
| printf | `%s` `%d` `%@` `%1$s` `%.2f` | Android, iOS, C, PHP, gettext |
| ICU | `{count, plural, other {# รายการ}}` | FormatJS, ARB (Flutter), Android บางแบบ |
| เกม | `[PlayerName]` `<item>` `$gold$` | แล้วแต่เอนจิน |
| แท็ก | `<b>...</b>` `<a href="...">...</a>` `<br>` | HTML, Android, Unity |
| ขึ้นบรรทัด | `\n` | ทุกแบบ |

**กฎ:**

1. ห้ามแปลคำในตัวแปร `{name}` ห้ามเป็น `{ชื่อ}`
2. ย้ายตำแหน่งตัวแปรในประโยคได้ เพื่อให้ลำดับคำเป็นภาษาไทย
3. ถ้ามีตัวแปรแบบ `%s` หลายตัวที่ไม่มีเลขตำแหน่ง และภาษาไทยต้องสลับลำดับ ห้ามสลับ ให้คงลำดับเดิม แล้วแจ้งในบันทึกว่าควรเปลี่ยนเป็น `%1$s` `%2$s`
4. แปลข้อความในแท็กได้ แต่ห้ามแปลชื่อแท็กและค่าในแท็ก เช่น `href`
5. ข้อความรอบตัวแปรต้องอ่านได้กับทุกค่าที่เป็นไปได้ เช่น `{count} items` เป็น `{count} รายการ` ใช้ได้ทั้ง 1 และ 100

**ตัวอย่าง:**

```
en: "Welcome back, {name}!"
th: "ยินดีต้อนรับกลับมา {name}"

en: "%1$s liked your photo"
th: "%1$s ถูกใจรูปภาพของคุณ"

en: "You have {count} new messages"
th: "มีข้อความใหม่ {count} ข้อความ"
```

## 6. พหูพจน์

ภาษาไทยไม่เปลี่ยนรูปคำตามจำนวน ตามมาตรฐาน CLDR ภาษาไทยมีรูปพหูพจน์แบบเดียวคือ `other`

- **ICU:** คงโครง `{count, plural, ...}` ไว้ แปลข้อความในทุก branch ที่ต้นฉบับมี ข้อความไทยของแต่ละ branch เหมือนกันได้ แต่ต้องมี `other` เสมอ
- **Android `<plurals>`:** ภาษาไทยใช้แค่ `<item quantity="other">` ถ้าโครงการต้องการให้มีครบทุก item ตามต้นฉบับ ให้ใส่ข้อความเดียวกัน
- **iOS `.stringsdict`:** ใช้ key `other`
- **gettext (PO):** ภาษาไทย `nplurals=1` ใส่แค่ `msgstr[0]`

```
en: "{count, plural, one {# file} other {# files}}"
th: "{count, plural, one {# ไฟล์} other {# ไฟล์}}"
```

## 7. ความยาวและการแสดงผล

- ข้อความไทยมักกว้างพอๆ กับอังกฤษหรือสั้นกว่า แต่สระบนล่างและวรรณยุกต์ต้องการความสูงบรรทัดมากกว่า ถ้าผู้ใช้บอกว่าข้อความถูกตัด ให้เสนอคำสั้นลง
- ภาษาไทยไม่เว้นวรรคระหว่างคำ ระบบตัดบรรทัดบางระบบตัดกลางคำ ข้อความยาวในพื้นที่แคบควรสั้นพอที่จะไม่ต้องตัดบรรทัด
- เว้นวรรคหน้าและหลังตัวเลขและคำภาษาอังกฤษตามที่ทั้งแอปใช้ เลือกแบบเดียวทั้งไฟล์

## 8. วันที่ เวลา ตัวเลข เงิน

- รูปแบบวันที่และเวลาที่มาจากตัวแปร ปล่อยให้ระบบจัดตาม locale ห้ามเขียนทับ
- ข้อความที่เขียนวันที่ตายตัว ใช้รูปแบบที่แอปใช้อยู่ ถ้าไม่มี ให้ใช้ "25 ต.ค. 2026" หรือตามที่ผู้ใช้กำหนด ปี พ.ศ. ใช้เมื่อแอปหรือผู้ใช้กำหนด
- เงินบาท ใช้ "฿" หรือ "บาท" แบบเดียวทั้งแอป
- ห้ามเปลี่ยนค่าของตัวเลข

## 9. เว็บไซต์

- **หัวข้อหลักและข้อความโฆษณา:** แปลแบบเขียนใหม่ได้ (transcreation) แต่ต้องไม่เกินจริงกว่าต้นฉบับ (TH09) และไม่เติมข้อมูล
- **title และ meta description:** แปลให้สั้นพอสำหรับผลการค้นหา คงชื่อแบรนด์ไว้ต้นหรือท้ายตามต้นฉบับ
- **URL, slug, id, class:** ห้ามแปล
- **alt ของรูปภาพ:** แปล
- **หน้ากฎหมาย** (ข้อตกลงการใช้งาน นโยบายความเป็นส่วนตัว): ใช้ `ทางการ` แปลให้ครบทุกข้อ และแนะนำในบันทึกให้ฝ่ายกฎหมายตรวจ
