# รูปแบบไฟล์

ไฟล์ที่แปลแล้วต้องเปิดได้และใช้แทนไฟล์ต้นฉบับได้ทันที กฎรวมคือ **แปลเฉพาะข้อความที่คนจะเห็น ส่วนอื่นห้ามแตะ** และส่งไฟล์เป็น UTF-8

## ซับไตเติล

### SRT

```
12
00:01:04,200 --> 00:01:06,900
<i>Where are you going?</i>
```

- แปล: บรรทัดข้อความ
- ห้ามแตะ: เลขบล็อก บรรทัดเวลา บรรทัดว่างที่คั่นบล็อก
- คงแท็ก: `<i>` `<b>` `<u>` `<font color="...">`

### WebVTT

```
WEBVTT

NOTE ฉากเปิด

intro-1
00:00:01.000 --> 00:00:04.000 align:start position:10%
<v Maya>Where are you going?
```

- แปล: ข้อความใน cue
- ห้ามแตะ: `WEBVTT` บรรทัดเวลาพร้อมค่าตั้งท้ายเวลา (`align:` `position:` `line:`) ชื่อ cue บล็อก `STYLE` และ `REGION`
- `NOTE` เป็นหมายเหตุของคนทำไฟล์ ไม่ต้องแปล
- คงแท็ก: `<v ชื่อ>` `<c.class>` `<i>` `<b>` ชื่อในแท็ก `<v>` คงตามต้นฉบับ เว้นแต่ผู้ใช้ขอให้แปล

### ASS / SSA

```
[Events]
Format: Layer, Start, End, Style, Name, MarginL, MarginR, MarginV, Effect, Text
Dialogue: 0,0:01:04.20,0:01:06.90,Default,Maya,0,0,0,,{\i1}Where are you going?{\i0}
```

- แปล: เฉพาะช่องสุดท้าย (`Text`) ของบรรทัด `Dialogue:` ซึ่งอยู่หลังจุลภาคตัวที่ 9
- ห้ามแตะ: `[Script Info]` `[V4+ Styles]` ช่องเวลา ชื่อสไตล์ บรรทัด `Comment:`
- คงคำสั่งในวงเล็บปีกกา `{\i1}` `{\pos(...)}` `{\fad(...)}` และ `\N` (ขึ้นบรรทัด) `\h` (ช่องว่างไม่ตัดบรรทัด)
- ถ้าฟอนต์ในสไตล์ไม่มีตัวอักษรไทย เช่น ฟอนต์ตกแต่งบางตัว ให้แจ้งในบันทึก และเสนอฟอนต์ที่มีภาษาไทย เช่น Tahoma, Leelawadee UI, Noto Sans Thai ห้ามแก้สไตล์เองถ้าผู้ใช้ไม่ขอ

## ข้อความ UI

### JSON (i18next, react-intl, vue-i18n และแบบทั่วไป)

```json
{
  "cart": {
    "title": "Your cart",
    "items_one": "{{count}} item",
    "items_other": "{{count}} items"
  }
}
```

- แปล: ค่า (value) ที่เป็นข้อความ
- ห้ามแตะ: key ลำดับ key โครงสร้างซ้อน ค่าที่เป็นตัวเลข true false null
- escape `"` เป็น `\"` และคง `\n`
- key พหูพจน์ของ i18next (`_one` `_other`) ภาษาไทยใช้แค่ `_other` แต่ให้คงทุก key ที่ต้นฉบับมี แล้วใส่ข้อความไทยเดียวกัน
- ถ้า root key เป็นรหัสภาษา เช่น `"en": {...}` ให้เปลี่ยนเป็น `"th"` และบอกในบันทึก

### ARB (Flutter)

- แปล: ค่าของ key ปกติ
- ห้ามแตะ: key ที่ขึ้นต้นด้วย `@` (คำอธิบายและนิยาม placeholder)
- เปลี่ยน `"@@locale": "en"` เป็น `"th"`
- อ่าน `description` ใน `@key` เป็นบริบทประกอบการแปล

### PO (gettext)

```
#. Button on the checkout page
msgctxt "checkout"
msgid "Pay now"
msgstr ""
```

- แปล: ใส่คำแปลใน `msgstr`
- ห้ามแตะ: `msgid` `msgid_plural` `msgctxt`
- อ่าน `#.` เป็นบริบทจากนักพัฒนา
- พหูพจน์: ภาษาไทยใส่แค่ `msgstr[0]` และหัวไฟล์ควรมี `Plural-Forms: nplurals=1; plural=0;`
- ตั้งหัวไฟล์ `Language: th` ถ้ายังไม่มี
- เอาป้าย `fuzzy` ออกเมื่อแปลแล้ว

### XLIFF (1.2 และ 2.0)

- แปล: ใส่คำแปลใน `<target>` สร้าง `<target>` ถ้ายังไม่มี
- ห้ามแตะ: `<source>` ค่า `id` และ `resname`
- คงแท็กในบรรทัดทุกตัว เช่น `<x/>` `<g>` `<ph>` `<pc>` ใน `<target>` ให้ครบเหมือน `<source>`
- ตั้งภาษาปลายทาง: XLIFF 1.2 ใช้ `target-language="th"` ส่วน 2.0 ใช้ `trgLang="th"`
- ตั้งสถานะเป็นแปลแล้ว: 1.2 ใช้ `state="translated"` ส่วน 2.0 ใช้ `state="translated"` ใน `<segment>`

### iOS `.strings`, `.stringsdict` และ `.xcstrings`

```
/* Title of the settings screen */
"settings.title" = "Settings";
```

- `.strings`: แปลเฉพาะข้อความทางขวาของ `=` คง `;` ท้ายบรรทัด escape `\"`
- `.stringsdict`: แปลค่า string ใน key `other` และคง `%#@...@` กับ `NSStringFormatValueTypeKey`
- `.xcstrings` (String Catalog): เพิ่มภาษา `th` ใน `localizations` ของแต่ละ key ใส่ `stringUnit` ที่มี `state: "translated"` และ `value`

### Android `strings.xml`

```xml
<string name="welcome">Welcome, %1$s!</string>
<string name="app_name" translatable="false">MyShop</string>
```

- แปล: ข้อความใน `<string>` `<item>` ของ `<plurals>` และ `<string-array>`
- ห้ามแตะ: `name` และ `<string>` ที่มี `translatable="false"`
- escape: `'` เป็น `\'` `"` เป็น `\"` `&` เป็น `&amp;` `<` เป็น `&lt;` ถ้าไม่ได้อยู่ใน CDATA
- `<plurals>`: ภาษาไทยใช้ `quantity="other"` ดู `ui.md` หัวข้อพหูพจน์

### YAML (Rails และระบบอื่น)

- แปลค่า คง key และการเยื้อง
- เปลี่ยน root key `en:` เป็น `th:`
- ข้อความที่มี `:` หรือขึ้นต้นด้วยอักขระพิเศษ ต้องอยู่ในเครื่องหมายคำพูด

## บทเกมแบบ CSV และตาราง

```
ID,Speaker,Context,MaxLength,English,Thai
Q1_001,Elara,"First meeting, suspicious",80,"Who sent you?",
```

- หาคอลัมน์ให้ได้ก่อนว่าคอลัมน์ไหนคือ ID ต้นฉบับ คำแปล ผู้พูด บริบท ความยาวสูงสุด
- ใส่คำแปลในคอลัมน์ภาษาไทย ถ้าไม่มี ให้เพิ่มคอลัมน์ `Thai` ต่อท้าย และบอกในบันทึก
- ห้ามแตะ: คอลัมน์ ID และคอลัมน์ต้นฉบับ
- อ่านคอลัมน์ Speaker และ Context ทุกแถว เพื่อเลือกสรรพนามและน้ำเสียง
- เคารพ MaxLength ถ้ามี
- คงตัวคั่น (จุลภาค แท็บ อัฒภาค) ตามต้นฉบับ ข้อความที่มีจุลภาค ขึ้นบรรทัด หรือ `"` ต้องอยู่ในเครื่องหมายคำพูด และ `"` ข้างในเขียนเป็น `""`
- ถ้าผู้ใช้จะเปิดด้วย Excel แล้วภาษาไทยเพี้ยน แนะนำให้บันทึกเป็น UTF-8 with BOM

## ข้อความที่วางมาในแชต

- ไม่มีไฟล์: ส่งคำแปลเป็นข้อความธรรมดา แยกย่อหน้าตามต้นฉบับ
- ถ้าวางมาเป็นรายการ ให้ส่งเป็นรายการลำดับเดียวกัน
- ถ้าดูออกว่าเป็นข้อความ UI (สั้นๆ หลายบรรทัด เช่น ชื่อปุ่ม) ให้ใช้กฎของ `ui.md` แม้ไม่ได้มาเป็นไฟล์

## ไฟล์ยาว

- แปลทีละช่วง แต่ใช้อภิธานศัพท์และตารางตัวละครชุดเดียวกันทุกช่วง
- บอกทุกครั้งว่าส่งถึงบล็อกหรือ key ไหน และเหลืออีกเท่าไหร่
- ห้ามย่อไฟล์ด้วย "...ส่วนที่เหลือเหมือนเดิม" ไฟล์ที่ส่งต้องเอาไปต่อกันแล้วใช้ได้จริง
